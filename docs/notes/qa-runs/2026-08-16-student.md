Host source has the real router. Documents/notifications/user-settings still 401 JSON when anonymous (those apps are mounted).
2. **Demo student is not verified.** `manage.py shell`: `student@test.com` exists, `is_active=True`, **`is_email_verified=False`**. `coordinator@test.com` is verified. User table has **5** rows (not the full `seed_demo_readiness` set). Seed source sets `"is_email_verified": True` for the demo student — this DB did not.
3. **CMS unrestored** (public pass): `/` is default Wagtail welcome; `/programas/` 404. Out of student SPA scope except as shared env.

Login API (`POST /api/login/` with `login` + `password`): both **wrong** and **correct** student passwords return `401` `{"detail":"Email not verified. Please check your inbox for the verification link."}` — verification is checked **before** password (`accounts/services.py`). So the dedicated “invalid credentials” path was not isolatable.

Authenticated student chrome (dashboard, applications, profile, settings, documents, calendar, permission URLs **as a signed-in student**) was **not reachable**. Items below that need a session are **Blocked (env)**, not Fail.
