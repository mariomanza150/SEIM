# UI quirks audit — 2026-11-24

Synthetic review of student/staff SPA surfaces and related API contracts. No production data or real identities were used.

## Fixed in this PR (high impact)

| # | Issue | Root cause | Fix |
|---|--------|------------|-----|
| 1 | Application detail double-submit / double-delete | Submit/delete had no in-flight lock after confirm | `submittingApplication` / `deletingApplication` guards + disabled buttons |
| 2 | Application create/draft double-submit | `submitting` set only after async profile/client validation | Lock at start of `handleSubmit` / `saveDraft` |
| 3 | Stale application detail after queue next/prev | `usePageState` + detail loader applied every response | Request sequence in `usePageState`; id check in detail loader |
| 4 | Wrong dynamic form / host catalogs after fast program change | No seq on schema/host cascade fetches | Seq guards in `loadDynamicForm` and host destination fetches |
| 5 | Form treated 403/500 `{detail}` as field validation | `applyServerValidationErrors` always returned true | Detect field-shaped bodies only |
| 6 | Waitlist submit toasted as “submitted successfully” | API always returned success copy; UI ignored status | API returns `waitlisted` + `application_status`; UI toast |
| 7 | Document detail used bare `/media/` download links | Unauthenticated media URLs for private files | Authenticated `preview/` blob download/open |
| 8 | Document staff/admin gates missed superuser/`is_admin` | Role-string-only checks | Align with `canUseStaffReviewQueue` / `isAdmin` |
| 9 | Documents list empty on mobile + no pagination | `ResponsiveList` without columns; pagination inside desktop slot | Mobile columns/actions; pagination outside list |
| 10 | Silent filter/program load failures | Swallowed catches | Toasts on Documents filters + Nominations programs |
| 11 | `meta.testerOnly` routes reachable by any auth user | Guard never checked tester meta | Enforce via QA context + `authNavigation` |

## Remaining findings (prioritized)

### P0 — Architectural / privacy (not fully closed here)

1. **Public `/media/` serve for document uploads** (`seim/urls.py` media route + `documents/` upload_to). UI no longer links bare media for document detail, but anything that still exposes a media path (CMS, older emails, logs, other templates) remains sensitive. Prefer authenticated download endpoints only and non-guessable storage keys; consider disabling public media for private uploads.

2. **Staff status transitions without confirmation / workflow enforcement gaps** — coordinators can jump statuses from the detail sidebar; reject/complete lack confirm dialogs. Ops risk; needs product + workflow policy, not only a UI disable.

### P1 — Correctness / UX

3. **List fetch races** on Applications, Documents, CoordinatorReviewQueue (no request seq). Same class of bug as page state; extend the seq/AbortController pattern.

4. **Filter ↔ URL query one-way sync** on Applications and Review Queue — refresh re-applies stale `?status=` after the user cleared filters in-session.

5. **Empty states ignore active filters** on Applications/Documents/Review Queue (copy says “no data” instead of “no matches”).

6. **Document types filter may truncate** to first DRF page (page size 20) on Documents list; DocumentUpload already paginates — align list page.

7. **Silent soft-fails** on dashboard next-steps, notification dropdown mark-read, partner portal docs reload, eligibility preview catch clearing to “eligible-looking” empty, DeadlinesCalendar subscribe URL, AdminPrograms editor catalogs (partial `Promise.all` failure).

8. **CompactFilterBar offcanvas** on ~375px can clip long filter+preset content without a flex scroll shell.

### P2 — Polish

9. Mobile review-queue cards omit bulk select; staff agreement mobile actions omit partner/renewal.
10. Dynamic award status badges without `te()` fallback can show raw i18n keys for unknown API values.
11. Zero-byte upload allowed by client `validateDocumentFile` (type/size only).
